# Open Frame Studio v2026.46.0 — capability matrix

Broncontrole op 9 november 2026 voor [ecosysteemissue #6](https://github.com/OpenAEC-Foundation/open-frame-studio/issues/6). De desktopinstallers zijn gebouwd uit [`f95e283`](https://github.com/OpenAEC-Foundation/open-frame-studio/commit/f95e283d31f880f9eec9b225ec984c060016c7f3); de Docker- en SuperCloud-vervolgcode staat pas in een latere broncommit. Een bronimplementatie, een geslaagde build, een gepubliceerd bestand en een werkende installatie zijn vier verschillende bewijsniveaus. **Onbekend** betekent dat het vereiste bewijs niet is vastgesteld; het betekent niet automatisch dat de mogelijkheid ontbreekt.

De laatst gepubliceerde stabiele versie in de [releasegeschiedenis](https://github.com/OpenAEC-Foundation/open-frame-studio/releases) is v0.6.0. [v2026.46.0](https://github.com/OpenAEC-Foundation/open-frame-studio/releases/tag/v2026.46.0) is als **installer-prerelease** gepubliceerd; de tag verwijst naar broncommit `f95e283d31f880f9eec9b225ec984c060016c7f3`. Gebruik geen v0.6.0-bestand als acceptatiebewijs voor v2026.46.0. De [releasecontrole](release-readiness.md) beschrijft de functionele bètascope en de nog niet uitgevoerde praktijkproeven.

## Bibliotheek, API, MCP en platform

| Capability | Status voor v2026.46.0 | Bronbewijs en open acceptatie |
|---|---|---|
| Headless productkern / Rust SDK | **Broncode aanwezig, geen extern SDK-contract bewezen.** [`ofs-core`](../ofs-core/Cargo.toml) is een Rust library met openbare modules voor model, geometrie, validatie, export en import ([`lib.rs`](../ofs-core/src/lib.rs)). [`ifc_acceptance_fixture.rs`](../ofs-core/examples/ifc_acceptance_fixture.rs) gebruikt de kern binnen dezelfde workspace. | Benoem ondersteunde publieke entry points, feature- en versiecompatibiliteit, foutconventies en licentie; bouw een voorbeeld vanuit een **apart** consumerproject tegen een gepubliceerde of vast gepinde versie. |
| Native DLL / `.so` / .NET assembly | **Niet als product-SDK geleverd.** `ofs-core` definieert geen native `cdylib`/C-ABI. De `cdylib` in [`ofs-wasm`](../ofs-wasm/Cargo.toml) is voor de browser en bewijst geen Windows-DLL met stabiele exports. | Leg de bedoelde native distributie vast; lever en test DLL en Linux-equivalent of documenteer gemotiveerd waarom een andere SDK-vorm de eis vervangt. Vereist zijn ABI-, geheugen-, buffer- en foutconventies. |
| Eigen headless API | **Prototypebron aanwezig.** [`ofs-cloud`](../ofs-cloud/src/main.rs) biedt Axum-routes op poort 3456. Projecten staan alleen in een in-memory `HashMap` ([`storage.rs`](../ofs-cloud/src/storage.rs)); IFC, offerte en productie retourneren `not_implemented` ([`api.rs`](../ofs-cloud/src/api.rs)). Er is geen authenticatie te zien en CORS is permissief. | Publiceer een afgebakend API-contract, persistente opslag en autorisatie-/foutgedrag; lever een reproduceerbare rooktest. CI bouwt of test `ofs-cloud` momenteel niet als releaseproduct. |
| Product-MCP | **Geen productendpoint of adapter in deze broncontrole vastgesteld.** De desktopcommando's en Axum-routes zijn geen MCP-tools. | Kies transport, tools/resources en lees-/schrijfrechten, of documenteer een expliciet besluit om MCP buiten de productscope te houden; voer daarna een echte clienttest uit. |
| Claude Desktop/Code en connector | **Niet als integratie bewezen.** De UI bevat een directe AI-assistent met instelbaar Anthropic-eindpunt ([`AiAssistant.svelte`](../ui/src/components/panels/AiAssistant.svelte)); dit is geen bewijs van een MCP-server, Claude Desktop/Code-configuratie of interactieve connector. | Verbind en test een echte client; behandel een installeerbare bundle en een interactieve connector als afzonderlijke leveringen. |
| UI en OpenAEC Style Repo | **Lokale implementatie aanwezig.** Svelte-componenten gebruiken lokale [tokens](../ui/src/styles/tokens.css) met meerdere thema's via [`stores/ui.js`](../ui/src/stores/ui.js). [`ui/package.json`](../ui/package.json) bevat geen directe Style Repo-pakketdependency. | Leg component- en tokenmapping naast de **huidige** Style Repo-versie vast; een naam of lokale tokencomment bewijst die aansluiting nog niet. |
| Release signing | **Windows NSIS geverifieerd.** De releaseworkflow gebruikt Azure Trusted Signing. Beide gedownloade NSIS-bestanden zijn op Windows opnieuw met `Get-AuthenticodeSignature` gecontroleerd: status `Valid`, signer Impertio Studio B.V., tijdstempel Microsoft Public RSA Time Stamping Authority. macOS Developer ID/notarization en Linux pakket/detached signing zijn niet aangetoond. De aparte [Docker-workflow](../.github/workflows/docker-image.yml) gebruikt Cosign voor een containerimage; dat tekent geen desktopinstaller. | Test de installers op schone machines; leg eventuele updater-signatuur apart vast en onderzoek gewenste macOS/Linux-ondertekening. |
| AWS | **Geen headless AWS-runtime bewezen.** De [`Docker-workflow`](../.github/workflows/docker-image.yml) beschrijft een grafische desktopapp die naar de browser wordt gestreamd via GHCR. Dat is geen ECS/Lambda-API of AWS-deploybewijs. | Kies runtime; lever deploymentdefinitie, configuratie/secrets, IAM/authenticatie, health/logging en een API-rooktest in de beoogde AWS-omgeving. Als AWS buiten productscope valt, documenteer het productbesluit. |

## Licentie en beslissingen

[`LICENSE`](../LICENSE) bevat CC BY-SA 4.0, terwijl [`Cargo.toml`](../Cargo.toml) en twee appschermen AGPL-3.0 noemen. Deze tegenstrijdigheid bestond al in de eerste broncommit en wordt door deze matrix niet opgelost. De rechthebbenden moeten vastleggen welke licentie voor broncode en binaries geldt voordat de metadata als één consistent contract kan worden gepresenteerd. Zie ook de [releasecontrole](release-readiness.md).

Deze matrix voltooit het **documenteren van de bronstatus** voor issue #6 zodra zij op de hoofdbranch is gepubliceerd. Nog open zijn: installatietests van één versie op schone Windows/macOS/Linux-machines; een extern SDK-voorbeeld en eventueel native ABI; een productiegeschikte API; een MCP-/Claude-besluit of implementatie met clienttest; Style Repo-vergelijking; macOS/Linux-ondertekeningsbewijs en updaterbeleid; AWS-scope en rooktest; en versiegebonden bewijslinks voor elke gekozen levering. Geen van die punten wordt door de aanwezigheid van deze matrix automatisch afgevinkt.
